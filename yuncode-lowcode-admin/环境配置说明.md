# 项目环境配置说明

## 📋 环境类型

项目有三种环境模式：

1. **开发环境 (development)** - 本地开发时使用
2. **生产环境 (production)** - 生产部署时使用
3. **预览环境 (preview)** - 本地预览构建结果时使用

## 🔍 判断当前环境

### 1. 在代码中判断环境

Vite 提供了内置的环境变量：

```typescript
// 判断是否为开发环境
if (import.meta.env.DEV) {
  console.log('当前是开发环境')
}

// 判断是否为生产环境
if (import.meta.env.PROD) {
  console.log('当前是生产环境')
}

// 判断是否为预览环境
if (import.meta.env.MODE === 'preview') {
  console.log('当前是预览环境')
}

// 获取当前模式
console.log(import.meta.env.MODE) // 'development' | 'production' | 'preview'
```

### 2. 在配置文件中使用环境判断

已更新 `src/config/index.ts`：

```typescript
export const getConfig = () => {
  if (import.meta.env.DEV) {
    // 开发环境配置
    return {
      ...apiConfig,
      ...devConfig,
    };
  } else {
    // 生产环境配置
    return {
      ...apiConfig,
      ...prodConfig,
    };
  }
};
```

## 🚀 运行命令

### 开发环境 (Development)

```bash
npm run dev
```

- 自动加载 `.env.development` 配置
- 启用热更新 (HMR)
- 显示详细的错误信息
- 使用开发环境 API 地址

### 生产环境 (Production)

```bash
# 1. 构建生产版本
npm run build

# 2. 预览构建结果（可选）
npm run preview
```

- 使用 `.env.production` 配置
- 代码压缩优化
- 移除调试代码
- 使用生产环境 API 地址

### 预览环境 (Preview)

```bash
npm run preview
```

- 预览生产构建的结果
- 本地启动静态服务器
- 使用 `.env.production` 配置

## 📁 环境变量文件说明

### 文件加载优先级

当运行项目时，Vite 按以下顺序加载环境变量文件（后面的覆盖前面的）：

1. `.env` - 所有环境都加载
2. `.env.local` - 所有环境都加载，会被 git 忽略
3. `.env.development` - 开发环境专用
4. `.env.production` - 生产环境专用
5. `.env.development.local` - 开发环境本地覆盖
6. `.env.production.local` - 生产环境本地覆盖

### 环境变量文件详解

#### `.env.example`
```env
# 示例配置文件，不会被加载
# 仅作为模板供用户参考
VITE_API_BASE_URL=http://localhost:8080
```

#### `.env.development`
```env
# 开发环境配置（会被提交到 git）
# npm run dev 时使用

VITE_API_BASE_URL=http://localhost:8080
```

#### `.env.production`
```env
# 生产环境配置（会被提交到 git）
# npm run build 或 npm run preview 时使用

VITE_API_BASE_URL=/api
```

#### `.env.local`
```env
# 本地覆盖配置（不会被提交到 git）
# 优先级最高，用于个人定制

VITE_API_BASE_URL=http://192.168.1.100:8080
```

## 📝 环境变量命名规范

**重要**：Vite 只会暴露以 `VITE_` 开头的环境变量到客户端代码。

### ✅ 正确的命名

```env
VITE_API_BASE_URL=http://localhost:8080  ✅ 会被暴露
VITE_APP_TITLE=My App                    ✅ 会被暴露
```

### ❌ 错误的命名

```env
API_BASE_URL=http://localhost:8080       ❌ 不会暴露
APP_TITLE=My App                          ❌ 不会暴露
SECRET_KEY=abc123                        ❌ 不会暴露（这也是好事）
```

### 在代码中使用

```typescript
// ✅ 正确
const apiUrl = import.meta.env.VITE_API_BASE_URL

// ❌ 错误 - 无法访问
const apiUrl = import.meta.env.API_BASE_URL
```

## 🔒 安全提示

### 敏感信息处理

1. **永远不要在客户端代码中存储敏感信息**
   - ❌ 数据库密码
   - ❌ API 密钥
   - ❌ JWT 密钥
   - ❌ 第三方服务密钥

2. **敏感信息应该放在后端**
   - 使用后端 API 代理请求
   - 后端验证权限和密钥

3. **环境变量文件**
   - `.env.local` 会被 git 忽略，适合本地配置
   - `.env.development` 和 `.env.production` 可以提交
   - 不要在提交的文件中包含敏感信息

| 性能优化 | ❌ 禁用 | ✅ 启用 | ✅ 启用 |
| API 地址 | 开发服务器 | 生产服务器 | 生产服务器 |

## 💡 最佳实践

1. **使用 `.env.local` 存放个人配置**
   - 本地数据库地址
   - 个人测试账号
   - 本地端口配置

2. **提交通用配置到 git**
   - `.env.development` - 团队通用开发配置
   - `.env.production` - 生产环境配置

3. **区分环境配置**
   - 开发环境：详细日志、本地 API
   - 生产环境：简洁日志、生产 API

4. **不要硬编码配置**
   - 使用环境变量
   - 使用配置文件
   - 避免魔法数字

5. **文档化配置**
   - 在 README 中说明必要配置
   - 使用 .env.example 提供模板
   - 注释复杂配置项
